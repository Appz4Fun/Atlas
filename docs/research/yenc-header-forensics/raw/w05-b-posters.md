# Wave 5 / Agent B: more posters from git clones (Haiku). The orchestrator checked the Nyuu adoption lines.
- Nyuu: header order Message-ID, Subject, From, Newsgroups, Date, Path, User-Agent (config.js:95-108). **Adopts a server-returned Message-ID when it differs from the one sent (lib/nntp.js:866-875, VERIFIED)**, and re-randomizes on retry unless keepMessageId.
- mbruel/ngPost: From, Newsgroups, Subject, Message-ID (NntpArticle.cpp:144-149). Message-ID `<QUuid Id128 (32 hex, no dashes)@signature>`. =yend `size= pcrc32=` with std::hex (unpadded), NO part= and NO crc32= (NntpArticle.cpp:66-70). Does not read the 340 ID. No Date, no UA.
- Hydro74000/ngPost fork: same, but `=yend size=N pcrc32=%08x` is zero padded (NntpArticle.cpp:190), and CR/LF are stripped from header values. Unpadded vs padded = version marker.
- postie (kipsilabs, javi11): headers come from a Go map, so wire ORDER IS RANDOM per article (article.go:89-105). Message-ID `{32 alnum}@{8}.{3}` (article.go:164-177), or nxg IDs. From `{14} <{14}@{5}.{3}>`. Date `UTC().Format(RFC1123Z)` = "+0000". Subject `[n/N] "name" - yEnc (p/P)`. yEnc via mnightingale/rapidyenc (template not checked). Article size 750000 (config.go:575).
- newspost (C): From, Newsgroups, Subject, User-Agent (+Reply-To/Followup-To) (nntp.c:102-108), with NO Message-ID or Date, so the server assigns both. Single-part `=ybegin line= size= name=` / `=yend size= crc32=%08x`. Multi-part `=yend size= part= pcrc32=%08x` plus crc32 on the last part (encode.c:93-120).
- NOTE: ngPost "=yend without part=" collides with NewsUP's trailer. Tell them apart by Message-ID shape and From charset (NewsUP letters only).
