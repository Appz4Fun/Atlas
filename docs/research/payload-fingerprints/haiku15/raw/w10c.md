# W10C key index at scale (10:52Z)
- RocksDB random-key WA ~4.6x, read p50 2.5-3 us (single-machine bench, hackernoon). rust-rocksdb ~2.2k stars, fjall ~2.3k.
- Entry ~20-30 B; interval keys can push entries to 1e9+ (25+ GB). Append-only sorted runs + sparse index (one-level LSM) fits; matches Atlas's write-our-own leaning.
- Filters: Bloom 9.6 bits/key at 1%, 19.1 at 0.01%; binary fuse within 13% of bound (arXiv 2201.01174), static -> one per immutable run; xorf ~764 stars; cuckoo for mutable sets.
- Union-find: 4-8 B/node mmap (400-800 MB at 1e8). Cannot split; store every edge with evidence, keep cluster id as a cache, recompute one component by BFS on retraction.
- My math: grid at LCM(716800,768000)=10.75 MB gives ~5,600 interval keys for a 60 GB file per tool pair; store only for files > grid size, and only for size pairs actually seen.
