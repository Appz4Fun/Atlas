# w10c: Where the original release name leaks inside an obfuscated Usenet post

Status: research notes. Items marked UNVERIFIED were not confirmed from source or spec in this run.
Fetch budget: about 18 WebFetch calls. Several raw.githubusercontent and parchive.github.io URLs returned client_error, so the ngPost help text, ngPost Main.cpp, and the Nyuu options were not read directly.

## Deobfuscation heuristics (what the indexer can mirror)

| Tool | Signals used | Reads inner archive names | Source |
|---|---|---|---|
| SABnzbd deobfuscate_filenames.py | decode_par2 renames a file to the PAR2 FileDesc name when the 16 KB MD5 matches. is_probably_obfuscated uses regexes: 32 hex; 40+ hex or dots; 30+ hex plus two [tokens]; starts with abc.xyz; default is obfuscated. get_biggest_file requires the largest file to be more than 3 times the second. | No. It works on on-disk names only. | https://raw.githubusercontent.com/sabnzbd/sabnzbd/develop/sabnzbd/deobfuscate_filenames.py |
| NZBGet ParRenamer (ParRenamer.cpp) | LoadParFile reads FileDesc name and hash16k. CheckRegularFile hashes the first 16 KB of each file and renames on match. IsSplittedFragment protects .000 and .001 parts. | No. Uses FileDesc and on-disk names. | https://raw.githubusercontent.com/nzbgetcom/nzbget/develop/daemon/postprocess/ParRenamer.cpp |
| NZBGet RarRenamer (RarRenamer.cpp) | RarVolume::Read gives inner names. MakeSets compares the first and last inner file names to join split files. RenameFiles picks the largest RAR by size (FindMainFile) and uses its on-disk name as the base. | Yes, for set matching only. Inner names do not supply the rename target. | https://raw.githubusercontent.com/nzbgetcom/nzbget/develop/daemon/postprocess/RarRenamer.cpp |

## Takeaways

- The PAR2 hash_16k and hash_full pair is the cheapest proof of a twin. It needs the index .par2 only, and it survives every rename. Match on hash, not name.
- PAR2 FileDesc is the main name leak. It is only useful if the PAR2 set was built before renaming, and the timing for ngPost and Nyuu is UNVERIFIED. Test this on real posts before relying on it.
- RAR inner names and the RAR5 archive comment (CMT) are the cheapest name leaks inside the payload. Both sit in the first volume, so one article is usually enough. ngPost --gen_name only randomizes the archive name, so inner names survive unless -hp is used.
- SABnzbd and NZBGet do not read inner archive names to pick the rename target. NZBGet's RarRenamer reads them only to match split sets. This means a deobfuscator would miss the release name in RAR headers, so the indexer must read them directly.
- NFO, SFV, MKV tags, and MP4 metadata were not checked in this run (UNVERIFIED). Read them only after the cheap leaks (PAR2 index, first RAR header) fail.
