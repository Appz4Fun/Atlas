# Wave 3 merged (07:52-08:01Z)
- Predicting sibling IDs: NxG-mode uploads (postie nxg, nxg-upper) are fully derivable: id = sha256("{hdr}:{type}:{n}"); the header's random part is seeded by UnixNano anchored on the first Date, ~15.5 us per seed (+-1 s on Linux ~8 min on 32 cores), then N STATs. newsmangler IDs are near-exact (<10 STATs per sibling). GoPostStuff is too wide; Nyuu/ngPost/postie default need PRNG work (the yEnc Opus thread has a tested V8 solver). NewsUP IMITATES other tools' Message-ID formats (incl. misspelt @gpoststuff), so classifier needs real-vs-imitation tells.
- STAT mechanics: 223/430, pipelinable, group-independent, but some servers want a GROUP first; nntppool runs 100 in flight on 20 conns; 430s get negative-cached (probe fills late); call it missing only when every provider 430s.
- Session shape: files tile in time; equal RAR volumes give identical last-part sizes (a cross-group key from XOVER :bytes); ngPost file order par2 index -> rars -> pow2 vol par2s; reorder width ~2N estimates connection count; throttled uploads are strictly periodic.
- Clock: one BODY of part01 gives RAR4 DOS local mtime + MKV DateUTC -> uploader UTC offset and mux-to-post latency; RAR5 time format flag says Windows vs Linux packer; ParPar creator leaks CPU arch; INN server IDs <radix32(time)$radix32(pid)$count@host> link one connection; Nyuu offset drift is a Kohno-style clock-skew fingerprint (weak under NTP).
