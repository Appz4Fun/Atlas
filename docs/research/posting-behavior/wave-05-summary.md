# Wave 5 merged (08:56-09:07Z)
- SIMULATION ROUND 2 (sim/sim2_*.py): XOVER alone can't cut file runs. A file's short last article arrives EARLY (it uploads fastest); about N/2 full-size articles straggle in after it, and concurrent uploads in one group interleave. Run accuracy falls to .07-.65 and no whole upload came out right. So Atlas must read the yEnc =ybegin part/total/size line for candidates. With header-based runs, restricting links to files whose sizes appear in the same PAR2 set lifts precision to .97-.99 and roughly doubles whole-upload correctness (.33->.67, .35->.78). Hungarian matching adds only 1-4 points.
- HIGHWINDS SERVER IDS DECODED: <T.N$S.R@fxNN.site>: T = little-endian base-64 seconds since 1997-10-12 08:38:20 UTC (matched NZB dates exactly 4/5), N = posting-host counter +1 per article, S = constant per upload session. Same S + host + tiling N = one upload across groups, readable from XOVER, identical on every provider. (The yEnc Haiku thread reached the same structure from 658 IDs.)
- REAL HEADERS: binary backbones strip Path (not-for-mail / path-stripped), Injection-Info and real NNTP-Posting-Host. HEAD still gives X-Received-Body-CRC/Bytes (Highwinds, Omicron, Usenet.Farm), Organization/X-Complaints-To (injecting provider), Giganews X-Trace. XOVER on Highwinds: Lines empty, 2-digit-year Date, full Xref. Abavia readers synthesize article numbers over 14 days (so arrival-order numbers are not raw there).
- CO-REMOVAL PROBE: 451 = documented DMCA removal (Giganews), 430 ambiguous, STAT/HEAD can say present after BODY is gone. SABnzbd, NZBGet, nntppool and the Rust nzb-nntp crate all mishandle 451 (nzb-nntp marks the connection broken). Partial "just enough to break PAR2" removal is now common, so use 4-6 canaries per file, pipelined STAT with BODY confirmation, polling every 10-15 min for 6 h then backing off, one account per independent backbone. Cost: 1M STATs ~0.15 GB.
