# Wave 4 merged (08:25-08:35Z)
- SIMULATION (research/posting-behavior/sim/): the end-to-start join works. With 20 obfuscated + 40 competing uploads over 4 groups: precision .975 / recall .942 per file link, using Date seconds ordered by article number inside each second ("within-second rank") and a window [-1.2*width/rate - 0.5 s, +0.5 s]. Raw 1-s Date drops recall to ~.77. Interpolating arrival from high-water-mark samples fails (+-10 s errors). Reorder width ~0.75 x connections. Weak spot: only ~2/3 of uploads come out with every link right, so chains need confirming (cumulative yEnc size vs PAR2/NZB totals) or a global assignment.
- UPLOADER PROFILES: publishing is Zipf-concentrated (3% of publishers post ~2/3 of content in BitTorrent studies), so ~100-500 profiles cover most. NewsUP's per-article random group subsets reveal the uploader's exact group pool within ~10 articles (a durable set ID); Nyuu default From leaks $USER@hostname. Method: Rich-header-style tiered hashes of the settings tuple, FP-STALKER rules for tool upgrades (versions only go up, after release date), Li et al. VLDB 2011 decay-weighted temporal linkage, MinHash/LSH on group pools.
- TAKEDOWNS: OS3 2015 saw removals as all-or-nothing per fileset (co-removal = strong signal), but 2012 forum cases and newer claims show scattered partial removal. A 2026 retention probe found STAT/HEAD can say "present" when BODY is gone (451), so probes must hit BODY. Some providers served marker articles ("dmca'd", "Blocked Article <blocked@article>"). Lumen has no Usenet Message-IDs; notices go by email. Senders work from indexer NZBs and Spotnet, so takedown clusters mirror existing groupings.
