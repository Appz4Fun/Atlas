# W6c: PAR2 + SFV + SRR metadata extractor (prototype)

Status: prototype, compiles, unit tests pass (3/3), truncation sweep clean. Source: `docs/research/archive-metadata/proto/par2_sfv_srr_meta.rs` (697 LOC, single file, deps `md-5` 0.10 and `crc32fast` 1.5). Built as a binary `par2meta` in scratchpad `w6c`.

## What works
- **PAR2**: scans every `PAR2\0PKT` occurrence; checks declared length (>=64, %4, in range, not past buffer), packet MD5 over bytes 32..end against header bytes 16..32; records truncated (length past end of buffer) and bad-MD5 packets separately. Parses Main (slice size, file count, non-recovery vs recovery IDs), FileDesc (length, MD5, MD5-16k, name), IFSC (per-slice MD5 + CRC32), RecvSlic (exponent, size), Creator, CommASCI, CommUni (UTF-16LE assumed), UniFileN (UTF-8 assumed). Groups packets by Recovery Set ID; counts packets per type per set.
- **Whole-file CRC32** from IFSC: slice CRCs are combined with `crc32fast::Hasher::combine` / `new_with_initial_len`. The last slice is zero-padded in IFSC, so its CRC is un-padded first (`unpad_crc`). Un-padding is exact register algebra: L(D||0^p) = shift_{8p}(L(D)) because L(zeros)=0, so L(D) = unshift(...) and re-apply the 0xFFFFFFFF init/xorout. Inverse of one zero-bit step is O(1) (bit 31 of result == bit 0 of input, since POLY has bit 31 set). No SABnzbd code used.
- **Creator classification**: ParPar (verified format `ParPar v<ver> <arch> [url]`, parsed into version and arch), par2cmdline (plus turbo/tbb/-mt variants), MultiPar/par2j, QuickPar, phpar2. Non-ParPar strings are marked UNVERIFIED in the output.
- **SFV**: `name crc32` lines (name may contain spaces, CRLF handled), `;` comment lines captured verbatim (first 32), unparsed-line count.
- **SRR**: block headers (CRC16 kept but not verified, type, flags, head_size, ADD_SIZE when 0x8000), 0x69 app name, 0x6A stored file (name, declared size, bytes present, truncated flag), 0x6B OSO (size, hash bytes, name), 0x71 RAR volume name, 0x6C padding, embedded RAR 0x72-0x7B (type counts only; data skipped only for types carrying ADD_SIZE, excluding FILE/SUB).
- **Never panics**: all reads go through `get()`/checked arithmetic; the test `never_panics_on_garbage` runs random buffers through all three parsers; shell sweep over every prefix length (0..=size) of `sample.par2`, `sample.srr`, `sample.sfv` gave 0 non-zero exits and 0 panics.

## Failures and gaps (honest)
- **No real-world samples.** `par2` is not in apt on the container (`apt-get install par2` failed: no package). No ParPar/par2cmdline/MultiPar `.par2` file was obtained, so every fixture is self-generated by `gen_fixtures.py` (Python, hashlib+zlib). Fixture validity only checks my reading of the spec and the CRC math (zlib agreement is a real check; packet MD5 and Recovery Set ID derivation were produced by the same author, so they are self-consistent, not independently verified).
- **No pyrescene SRR sample** was fetched. SRR fixture is hand-built per the w5b block table; RAR embedded-block skipping rules are from that table, not from a real SRR.
- UniFileN payload encoding (UTF-8 assumed) and CommUni (UTF-16LE assumed) are unverified. Creator strings for MultiPar, QuickPar, phpar2 are unverified; par2cmdline version parsing is a guess ("version X").
- Set ID in the fixture = MD5 of Main body; the tool does not verify Recovery Set ID.
- Performance: un-padding is bit-serial, O(8 * slice_size) per file, roughly 3M steps for a 384 KB slice (fine). For 100 MB slices it is ~800M steps per file, which needs GF(2) matrix exponentiation or a precomputed table.
- Whole file is read into memory (`fs::read`). Prototype only; large `.vol` files need streaming.
- Detection order is PAR2 magic first, then SRR (`0x69` at byte 2 and block type 0x69 first), then SFV. A plain text file with no valid `name crc` lines reports "unknown".
- Not done: PAR3, packed packets (PkdMain/PkdRecvS) are only counted, no parsing; RFSC/FileSlic counted only.
