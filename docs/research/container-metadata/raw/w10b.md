# w10b: byte-budget measurements on synthetic grain sources

Caveat: encoder and noise settings shape every number here. Sources are testsrc2 plus `noise=alls=30:allf=t+u` (worst-case grain), 10 s, one run, no repeats. x265/x264 use ABR with superfast presets, so the first GOP is front-loaded. Treat these as order-of-magnitude budgets, not content-typical sizes.

## Commands (scripts in /tmp/w10b: gen.sh, gen2.sh, measure.py)

```
# audio sources
ffmpeg -f lavfi -i "anoisesrc=d=10:c=pink:r=48000:a=0.25" -filter:a "pan=5.1|c0=c0|c1=c0|c2=c0|c3=c0|c4=c0|c5=c0" -c:a pcm_s24le aud51.wav
ffmpeg -i aud51.wav -c:a eac3 -b:a 640k -ac 6 a.eac3
ffmpeg -i aud51.wav -strict -2 -c:a truehd -f truehd a.thd        # truehd is experimental; needs -strict -2 after -i
# video
ffmpeg -f lavfi -i "testsrc2=size=3840x2160:rate=24000/1001,noise=alls=30:allf=t+u" -t 10 -pix_fmt yuv420p10le -c:v libx265 -preset superfast -b:v 40M -maxrate 40M -bufsize 80M -x265-params keyint=48:min-keyint=48:scenecut=0:log-level=error -f hevc v4k.hevc
ffmpeg -f lavfi -i "testsrc2=size=1920x1080:rate=24000/1001,noise=alls=30:allf=t+u" -t 10 -pix_fmt yuv420p -c:v libx264 -preset superfast -b:v 12M -maxrate 12M -bufsize 24M -g 48 -keyint_min 48 -sc_threshold 0 -f h264 v1080.h264
# mux (mkvmerge v82 here rejected --fps; --default-duration used instead)
mkvmerge -o 4k_hevc10.mkv --default-duration 0:41708333ns v4k.hevc --language 0:eng a.eac3 --language 0:eng a.thd --language 0:eng s_en.srt --language 0:fre s_fr.srt
mkvmerge -o 1080_x264.mkv --default-duration 0:41708333ns v1080.h264 --language 0:eng a.eac3 --language 0:eng a.thd --language 0:eng s_en.srt --language 0:fre s_fr.srt
# 200-style ASS (34 KB CodecPrivate) + 2 x 5 MB random font attachments
mkvmerge -o big_ass_fonts.mkv --default-duration 0:41708333ns v1080.h264 --language 0:eng a.eac3 big.ass --attachment-mime-type application/x-truetype-font --attach-file font_a.ttf --attachment-mime-type application/x-truetype-font --attach-file font_b.ttf
# measure (stdlib EBML walker; frame-level, lacing-aware; offsets are frame end positions in file order)
python3 -I /tmp/w10b/measure.py FILE.mkv
```

Reading the table:
- Fits-the-budget row is a plain check against the alt-key coverage figure. A needs 4.99 MB, so it misses 4 MB. B needs 1.62 MB, so it misses 1.4 MB and fits 4 MB.
- C has zero A/V bytes in the first ~10.5 MB. The first 700 KB, 1.4 MB and 4 MB articles carry no media. Full alt-key coverage needs ~11.8 MB, about 17 articles of 700 KB.
- The alt-key coverage line is the max of the 8th video end and the 16th E-AC-3 end. It is not a per-track figure.
- The 8-video and 16-audio numbers use file (decode/interleave) order.

## Caveats

- Noise settings dominate: pink-noise 6ch TrueHD runs about 6 Mbps and testsrc2 + noise is worst-case for video. Real content is smaller.
- ABR warm-up front-loads bits. First 8 frames average 575 KB at 4K (file average 215 KB) and 159 KB at 1080p (file average 66 KB). Coverage figures are pessimistic. CRF or 2-pass would move them.
- The IDR is the dominant term. A keyframe interval of 48 frames (2 s) makes the IDR about 0.97 MB at 4K.
- Audio blocks use fixed-size lacing (lacing 2) in mkvmerge v82, so frame-level parsing was needed.
- Fonts are random bytes (incompressible). Real fonts would be somewhat smaller.
- Single run, one encoder preset per profile, no repetitions.
